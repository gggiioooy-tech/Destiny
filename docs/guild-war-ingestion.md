# 길드전 기록 수신 계약

대상: 15월 Supabase 프로젝트 `kqygrszkbuzxmmfndhye`.
PC 자동 수집기 연결은 아직 구현되지 않았다. 이번 변경은 길드 탭, 집계/조회 화면 및 인증된 업로드 RPC를 제공한다. 실험용 캡처 기록은 업로드하지 않았다.

## 길드와 권한

- `guild_war_tabs`에 철폐·서리를 초기 등록한다.
- 최고 관리자만 `add_guild_war_tab(p_name)`으로 회원 메모의 쉼표 구분 길드명 중 하나를 추가한다. 다른 관리자/회원/게스트는 화면과 서버 모두에서 추가할 수 없다.
- 업로드는 유효한 Supabase 로그인 세션이 있는 승인된 회원/관리자만 가능하다. 소유자만 수정 가능한 `profiles.memo`를 서버가 읽는다. 클라이언트의 길드 이름/작성자 ID는 신뢰하지 않는다.
- 메모에 서로 다른 이름이 정확히 하나면 그 길드에 귀속된다. 탭 미등록 길드 기록은 저장하되 조회 대상에서 제외한다. 탭을 추가하면 이전 보류 기록도 보인다.
- 메모가 비었거나 여러 길드가 있으면 `guild_name=null`로 보류한다. 나중에 메모를 고쳐도 과거의 모호한 기록은 자동 재분류하지 않는다.
- 현재 두 탭은 승인 회원/관리자 공통 열람이며, 게스트와 비로그인은 조회할 수 없다.

## 업로드

`supabase.rpc('submit_guild_war_observation', {p_kind, p_source_key, p_occurred_at, p_payload})`

- `p_kind`: `battle` 또는 `defense_snapshot`.
- `p_source_key`: 같은 전투를 여러 수집기가 동일하게 식별하도록 전투 시각, 공격자/방어자 ID, 자리, 전쟁 식별자에서 만든 안정적인 해시. 스냅샷은 전쟁 ID/수집시각/내용 해시를 사용한다. 최대 200자.
- `p_occurred_at`: ISO 시각. 10분을 초과하는 미래 시각은 거부한다.
- `p_payload`: 최대 512KiB JSON 객체. 토큰, 계정 로그인 정보, 패킷 원문, 리플레이 URL을 넣지 않는다.
- 응답 `status`: `recorded`, `held`, `duplicate`. `guild`는 서버가 해석한 이름 또는 null.
- 같은 회원·종류·키의 재전송은 덮어쓰지 않는다. 전투 기록은 스킬 보강 등 정규화를 마친 뒤 업로드한다. 현재 API에 수정/삭제 기능은 없다.
- 클라이언트가 보내는 사실관계 자체의 진위 검증은 별도 수집기 과제다. 로그인/길드 권한 검증과 게임 데이터의 진위 검증은 구분한다.

전투 payload 예시:
```json
{"warDate":"2026-10-15","direction":"attack","castle":"외성1","attackerWon":true,"attacker":{"nickname":"공격자","heroes":["루디","스파이크","클레미스"],"pet":"연지","skills":[{"hero":"루디","skill":"아래"}]},"defender":{"nickname":"방어자","heroes":["델론즈","아일린","젠이츠"],"pet":"펫 이름","skills":[]}}
```

방어 스냅샷 payload 예시:
```json
{"warDate":"2026-10-15","total":90,"defenses":[{"castle":"외성1","nickname":"상대","heroes":["선란","탄지로","하연"],"pet":"연지"}]}
```

스냅샷은 해당 수집기가 확인한 전체 누적 목록을 전송한다. `total`을 모르면 생략한다. 전쟁 ID를 포함한 최신 스냅샷으로 관리해야 하며, 실제 전쟁일의 전체 수신/부분 수신 범위는 아직 미검증이다.
화면은 선택한 길드전 날짜의 최신 스냅샷 하나와 공격/방어 각각 최대 150개의 중복 제거된 전투 기록을 읽으며, 15초마다 표시 중인 탭을 갱신한다. 영웅 순서가 달라도 성/영웅 조합/펫이 같으면 합산한다. 추천 카운터는 기존 사이트의 상대 영웅 조합으로 매칭하며 상대 펫 호환성을 보장하지 않는다.

## 날짜와 공격/방어 구분

- 모든 업로드 payload에 `warDate`(YYYY-MM-DD)를 지정한다. 이는 업로드 날짜가 아닌 게임에서 확인된 길드전 시작 날짜이며, 자정을 지나도 같은 전쟁은 같은 날짜를 유지한다.
- battle에는 `direction: "attack" | "defense"`가 필수다. 소속 길드의 공격인지 방어인지를 수집기가 판별한다. 승패나 접속 회원이 직접 공격했는지로 추정하지 않는다.
- 현재 길드전은 수집된 날짜 중 가장 최근 것을 표시하고 그 날짜를 화면에 명시한다. 실제 진행 중 여부를 게임에서 아직 확인하지 못했으므로 진행 중이라고 단정하지 않는다.
- `guild_war_dates(p_guild)`는 RLS를 통과하는 날짜 목록을 반환한다.
- `guild_war_battles(p_guild,p_war_date,p_direction,p_castle,p_search)`는 해당 길드/날짜/방향을 분리하고 중복을 제거한 뒤 성별·검색 필터를 적용하고 최신 150건을 반환한다. 검색은 닉네임/영웅/펫의 공백을 제거한 부분 문자열 검색이다.
- 기존 방향 미확인 기록은 승패로 추측해서 분류하지 않는다. 초기 설치 당시 실전 업로드 기록은 없었다.
- `scripts/verify-guild-war-history.sql`: 양쪽 170건씩 넣고 150건 제한, 필터 후 제한 적용, 과거 날짜/타 길드 격리 및 권한을 트랜잭션 롤백으로 검증한다.
